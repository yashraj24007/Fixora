## � Overview
Fixora is an intelligent AI Vehicle Service Assistant that transforms how automotive technicians and vehicle owners interact with repair manuals. Our advanced RAG (Retrieval Augmented Generation) system processes PDFs locally, creates vector embeddings, and provides instant answers with precise citations.

---

## ❌ The Problem

In the automotive repair industry, technicians face:
- **Information Overload** – Thousands of pages across multiple manuals per vehicle.
- **Time Wastage** – Searching through physical manuals during critical repairs.
- **Knowledge Gaps** – Difficulty finding specific diagnostic procedures quickly.
- **Manual Complexity** – Technical jargon and scattered information.

---

## 💡 Our Solution

Fixora addresses these challenges with:
- 📄 **Smart PDF Processing** – Upload manuals and get instant searchability.
- 🧠 **AI-Powered Search** – Ask questions in natural language.
- 📍 **Exact Citations** – Get answers with precise page references.
- 🔒 **Privacy-First** – All processing happens in your browser.

---

## 🔄 How It Works

1. **Upload Manuals** → Add your vehicle repair PDFs to the system.
2. **AI Processing** → Documents are chunked and embedded using ML models.
3. **Ask Questions** → Query in natural language about any repair topic.
4. **Get Answers** → Receive precise responses with page citations.
5. **Smart Diagnostics** → Use guided troubleshooting for common issues.
6. **Stay Updated** → Access video tutorials and latest repair techniques.

## 🧠 How RAG Works (Technical Deep Dive)

### What is RAG?

**RAG (Retrieval Augmented Generation)** ensures AI answers come ONLY from your uploaded documents, not from general knowledge. This guarantees:
- ✅ **Accuracy** - Answers based on actual source material
- ✅ **Verifiability** - Every answer includes page citations
- ✅ **Privacy** - Documents processed locally in browser
- ✅ **Relevance** - AI uses YOUR manuals, not generic information

### The RAG Pipeline

```plaintext
📄 PDF Upload
    ↓
🔍 Text Extraction (pdf.js)
    ↓ Extracts text from every page
📑 Chunking (500 chars, 100 overlap)
    ↓ Splits into searchable segments
🧮 Embedding Generation (Transformers.js)
    ↓ Creates 384-dimensional vectors
💾 Vector Store (In-Memory)
    ↓ Stores chunks with embeddings
    
❓ User Question
    ↓
🧮 Query Embedding
    ↓ Convert question to vector
🔎 Semantic Search (Cosine Similarity)
    ↓ Find top 10 most relevant chunks
📚 Context Building
    ↓ Combine chunks with page citations
🤖 AI Generation (Groq)
    ↓ Generate answer using ONLY provided context
💬 Response with Citations
```

### Technical Specifications

| Component | Technology | Details |
|-----------|-----------|---------|
| **PDF Parser** | pdfjs-dist | Mozilla's battle-tested library |
| **Text Chunking** | Custom Algorithm | 500 char chunks, 100 char overlap |
| **Embedding Model** | Xenova/all-MiniLM-L6-v2 | 384 dimensions, runs in browser |
| **Vector Search** | Cosine Similarity | Measures semantic closeness |
| **AI Model** | llama-3.1-70b-versatile | Via Groq API (ultra-fast) |
| **Storage** | In-Memory | Cleared on page refresh |
| **Processing** | Client-Side | 100% browser-based (privacy!) |

### Why Browser-Based RAG?

**Privacy** 🔒
- PDFs never uploaded to servers
- All processing happens locally
- Your documents stay on your device

**Cost** 💰
- No embedding API costs
- Only pay for AI generation (Groq free tier: 30 req/min)

**Speed** ⚡
- No network latency after model download
- Instant semantic search
- Fast vector operations

**Offline Capable** 🌍
- Works without internet (after model download)
- Process PDFs anywhere

### Limitations & Solutions

| Limitation | Impact | Solution |
|------------|--------|----------|
| **In-Memory Storage** | Lost on page refresh | Future: IndexedDB persistence |
| **No OCR** | Scanned PDFs won't work | Use text-based PDFs only |
| **10MB File Limit** | Large manuals rejected | Split large PDFs into sections |
| **First-Time Model Download** | ~120MB download | One-time only, cached forever |
| **Processing Time** | 1-3 min per PDF | Normal for client-side processing |

## � Troubleshooting

### Common Issues & Solutions

#### 1. **"Processing failed" Error**
**Problem**: PDF upload fails during processing

**Causes**:
- PDF is a scanned image (no extractable text)
- PDF is password-protected or encrypted
- File corrupted or damaged
- File exceeds 10MB limit

**Solutions**:
- ✅ Use text-based PDFs (not scanned images)
- ✅ Remove password protection
- ✅ Try a different PDF
- ✅ Split large files into smaller PDFs

#### 2. **"No relevant information found"**
**Problem**: AI can't find answers in uploaded PDFs

**Causes**:
- Question uses different terminology than document
- Information doesn't exist in the PDF
- Document not fully processed

**Solutions**:
- ✅ Rephrase question using document's terminology
- ✅ Check if information actually exists in PDF
- ✅ Wait for "Ready" status before asking
- ✅ Try more general questions

#### 3. **Embedding Model Loading Slow**
**Problem**: First PDF takes very long to process

**Causes**:
- First-time model download (~120MB)
- Slow internet connection
- Browser caching issues

**Solutions**:
- ✅ Wait for one-time model download (cached after)
- ✅ Check internet connection speed
- ✅ Clear browser cache and retry
- ✅ Use faster internet for first use

#### 4. **"API Error" or "Failed to get AI response"**
**Problem**: Can't get answers from AI

**Causes**:
- Missing or invalid Groq API key
- API rate limit exceeded (30 req/min on free tier)
- Backend server not running
- Internet connection issues

**Solutions**:
- ✅ Check `.env.local` has correct API key
- ✅ Verify API key at [console.groq.com](https://console.groq.com/)
- ✅ Wait if rate limited (resets every minute)
- ✅ Ensure backend server is running (`npm run dev`)
- ✅ Check browser console for detailed errors

#### 5. **PDFs Lost on Page Refresh**
**Problem**: Need to re-upload PDFs after refreshing

**Cause**: In-memory storage (by design for privacy)

**Solutions**:
- ✅ This is expected behavior (privacy-first design)
- ✅ Keep browser tab open during session
- ✅ Future update will add IndexedDB persistence

#### 6. **Backend Server Won't Start**
**Problem**: Port 3001 already in use

**Solution**:
```bash
# Windows
netstat -ano | findstr :3001
taskkill /PID <PID> /F

# Mac/Linux
lsof -ti:3001 | xargs kill
```
